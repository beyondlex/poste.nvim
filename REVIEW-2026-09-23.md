## Verified clean rather than assumed

- **The redis `#`-comment fix has no Rust counterpart** (`poste-redis`'s
  `bf5440f`). The binary never parses `.redis` file text — Lua extracts token
  arrays (EXECUTION-PLAN D1, "the only parser") and `redis_session.rs` /
  `redis_exec.rs` receive argv — so a mid-word `#` reaching the server as part
  of a key was only ever a Lua-side truncation. The Rust SCAN branch
  (`redis_executor.rs`) that renders `[cursor, keys[]]` is likewise untouched
  by the fix.
- **The CSV/JSONB fixes have no Rust counterpart** (`poste-db`'s `62b35ca`,
  `5f3c358`). Export and CSV import live entirely in the plugins; the binary's
  JSON wire format delivers jsonb as a nested JSON value by design (the very
  shape that becomes a Lua table), and round 24's float rule is the only
  value-rewriting it does on the way out.
- **Non-test `unwrap`/`expect` scan.** Counting only lines before each file's
  `#[cfg(test)] mod tests`: `sql_connection.rs`, `sql_introspect/mod.rs` —
  zero; `poste-core/src/parser/mod.rs` — one, a `Regex::new` on a string
  literal with an `expect` message (`parser/mod.rs:502`), which cannot fail at
  runtime. Everything else the grep finds (48 in `sql_connection.rs`, 45 in
  `exec_file.rs`, …) is inside test modules, where a panic is the assertion.
- **`docs/schema.md` stayed true**: the asset/binary-lookup contract the
  09-22 docs commits wrote still matches `install.rs`'s candidate list and
  the `.exe` rule, checked against the commit that claimed it rather than
  re-derived from memory.
