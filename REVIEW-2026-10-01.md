## Change: the HTTP-era request/orchestration surface is gone

Round 17 deleted `formatter/tests.rs` because it had not compiled since
the HTTP removal. The files below are its twins that DID compile — their
tests ran, so every "605 green" report was partly counting tests of a
surface the binary stopped shipping at e40947a. Verified dead by grep
across the workspace (zero call sites) before cutting:

- `crates/poste-core/src/parser/` (`Parser`, `BlockMeta`, `VarResolver`):
  the `### request block` parser whose output fed `poste run --describe`
  — a subcommand main.rs no longer has. Plus `Request` (the struct only
  it consumed) and lib.rs's re-exports of all three.
- `sql_parser::{parse_sql_request, SqlParseResult, extract_database}`:
  the Request-shaped entry point. The CLI never calls it — it splits
  with `split_statements_with` and reads directives itself.
- `poste-exec::sql_executor::{execute_sql, make_response, build_response,
  StatementResult}` and the per-dialect `execute_{postgres,mysql,sqlite,
  mssql,clickhouse}` wrappers behind it: the old dispatch orchestrator.
  The cli's exec-file/session loops drive the connect/query helpers
  directly (`sql_exec_common` for the sqlx drivers, `mssql.rs`/
  `clickhouse.rs` for tiberius). `postgres.rs`/`mysql.rs`/`sqlite.rs`
  existed only for their wrappers and are gone; `value.rs` keeps exactly
  the converters the live mssql path uses (its int/float precision tests
  stay).

## Probed live, held

- `exec-file` on a fresh sqlite file: create/insert/select stream
  progress → result → summary (`succeeded:3, total_affected:2`), and an
  unterminated literal in statement 2 errors per-statement while the
  summary stays greedy and honest (`failed:1`).
- Empty file / comments-only file → `No SQL statements found in file`
  (the verdict `executor.lua` refuses blank SQL against).
- `session` hostile stdin: a non-JSON line errors with `seq:0` (never a
  Lua seq, so no pending slot can eat it) and the loop keeps serving; a
  blank `sql` is skipped silently while the next real request answers —
  the exact shapes `executor.lua`'s blank-refusal comment cites.
- `redis-exec` per the documented wire shape (`{connection, commands:
  string[][]}`): a number inside a command array is a clean stdin JSON
  error; the round-17 pins (`--max-items` truncation flags, string
  SCAN cursor) were re-confirmed on the fresh build.
- `introspect` and `context detect` answer normally after the removal.
