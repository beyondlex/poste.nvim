## Bugs fixed

1. **`install.lua` version sync was dead code with a landmine** — two stacked
   defects in `ensure()`:
   - `plugin_tag()` was a `local function` declared *after* its only call
     site, so the call compiled to a **global** lookup (nil at runtime): the
     scheduled version check would error whenever it ran. Same late-local
     trap as poste-db's `format.lua` `normalize_type`; luacheck's
     `ignore 113`/`ignore 211` pair on the two lines was the fingerprint.
   - The default `state.config.poste_binary` **is** the managed data path,
     so the step-1 early return fired before the sync's step-4 home was
     ever reached: for the default configuration the tag→binary sync could
     not run at all.
   `plugin_tag` now lives above `ensure()`, the sync is a shared
   `schedule_version_sync()` triggered by both the config-path and
   data-path branches, and the callback is pcall-wrapped.
   Test: `tests/poste/install_spec.lua` (sync runs on the managed-install
   path; the `vim.g.poste_binary` override never syncs; no global fallback).

2. **`layout.word_wrap` split multi-byte characters** — the byte-based
   `#text`/`sub` implementation hard-broke long text at arbitrary byte
   offsets: any width not divisible by the character width produced invalid
   UTF-8 for space-less CJK text (e.g. SQL comments in the create-schema
   preview). The old CJK test passed only because its width (9) happened to
   be divisible by 3 — a false-positive test. Rewritten to walk display
   widths per character with `strcharpart` cuts; a single character wider
   than the line is emitted rather than looping. Also fixed while there:
   `keymaps()` shaved a char off the prefix when `mapping` was empty, and
   `dynamic_line` could derive a negative keep-width when the content width
   was narrower than the ellipsis (now clamped).
   Tests: wrap at width 10 (not divisible by 3) with round-trip and
   display-width assertions, CJK-with-spaces wrap, single-wide-char, empty
   keymaps prefix, narrow `dynamic_line`.
