## Bugs fixed

1. **`split_statements` swallowed the newline that ended a `--` comment**
   (`crates/poste-core/src/sql_parser.rs`) — a comment with no space
   before it glued the tokens around it: `SELECT 1--c<newline>FROM t`
   split into `SELECT 1FROM t`, a syntax error at the server. The
   consumer now keeps the newline in the statement text as a separator.
   (`sql_context/tokenizer.rs` is token-based and positions stay
   faithful there — the bug was exclusive to the exec-file splitter.)

2. **schema.md was missing the `context stmt-ranges` subcommand** —
   shipped and used by poste-db's `statement.try_rust_stmt_ranges`, but
   absent from the family contract doc. Documented with its
   `[[start, end], ...]` reply shape.

3. **Cosmetic: a duplicated regression comment block** in
   `redis_executor.rs`'s char-boundary truncation test (09-17 carry).

## Recorded, not changed (with rationale)

- **`redis_session.rs` `needs_rescue` string-matches error text**
  ("connection"/"broken"/"dropped") — a protocol-classified error from
  the driver would be more precise, but the redis crate does not expose
  a stable error-classification API across the versions in play; the
  heuristic can only over- or under-rescue a single command, and the
  retry-on-fresh-connection is idempotent-safe for the read paths but
  NOT for blind writes (a rescued SET that actually landed runs twice).
  Recorded because the write-twice window is inherent to at-least-once
  rescue retries.
- **`mq_executor::json_to_field_table` skips JSON arrays** (documented
  at the definition — AMQP field arrays round-trip poorly through JSON).
  A header that arrives as an array is silently dropped on publish;
  surfacing that as an operation error would be the stricter contract.
