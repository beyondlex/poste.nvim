## Bugs fixed

1. **`split_statements` cut dollar-quoted bodies at inner semicolons**
   (`crates/poste-core/src/sql_parser.rs`) — the 09-11 round taught
   `blank_string_literals` (the classification view) about Postgres dollar
   quotes, but the statement splitter itself kept treating every `;` as a
   terminator: `CREATE FUNCTION f() AS $$ BEGIN SELECT 1; END $$ …` split
   into two broken statements and both halves failed with syntax errors at
   execution time (`exec_file.rs` and `parse_sql_request` both route through
   it). The splitter now consumes through the matching closing tag (`$$` or
   `$tag$`, same tag rules as `blank_string_literals`); `$1` placeholders and
   stray `$` stay literal. Tests: dollar-quoted body with semicolons, tagged
   `$fn$` bodies, non-tags untouched.

2. **Fallback float picker pinned the search line** (`lua/poste/select.lua`)
   — `pick_float` never positioned the cursor explicitly: the initial
   `startinsert!` landed after the prompt only by accident (EOL semantics),
   and once the cursor drifted off the search line (mouse scroll, Ctrl-F, …)
   `i`/`a` typed into the item list instead of the search input. The maps and
   the open path now focus the search line first. The banged `startinsert!`
   is load-bearing and documented in-code: builds that clamp
   `nvim_win_set_cursor` to len-1 leave the cursor on the prefix's trailing
   space, and appending *after* it keeps typed text past the prompt where the
   `TextChangedI` pattern still matches — the unbanged variant inserts inside
   the prompt and silently kills the live filter. Adds
   `tests/poste/select_spec.lua` for the float fallback (specs drive keymap
   callbacks via `maparg().callback`; headless `startinsert!` leaves a
   phantom pending-insert that eats the first Esc, so feedkeys-driven
   cancellation is order-dependent there).

## Recorded, not changed (with rationale)

- **`layout.columns` highlight offsets mix byte and display widths** — the
  offset accumulation assumes each padded part occupies exactly its column
  width in bytes, which breaks with non-ASCII titles in earlier columns.
  Current callers (poste-db `file_exec.lua` "DDL"/"DML") are ASCII-only, so
  no live mispositioning; fix together with a caller if CJK titles ever
  appear.
- **`promise.finally_` invokes a throwing `fn` twice** (once from `then_`,
  once from the `catch_` recovery) — the module still has zero callers
  across the ecosystem (carried from 09-08/09/11; deletion remains the
  better call unless a satellite adopts it).
- **`pick_snacks` reaches the global `Snacks` after requiring
  `snacks.picker`** — verified safe: `lua/snacks/init.lua` sets `_G.Snacks`
  and the picker module requires the parent, so the global exists whenever
  the require succeeds.
- **`split_statements` block comments are non-nesting** (`/* /* */ */`)
  while Postgres supports nesting — the splitter is a heuristic view, same
  standing as `blank_string_literals` not interpreting backslash escapes.
- Carried unchanged from 09-11: `#### ` lines treated as `###` block
  separators; HTTP header heuristic; clippy warnings informational.
