## Recorded, not changed (with rationale)

- **Resultset column `nullable` is a placeholder, not real nullability**
  (`exec_file.rs` / `session.rs`: `"nullable": col.type_info().name()
  != "BOOL"`). sqlx type_info carries no nullability, so the field is
  semantically wrong (a BOOL column is not necessarily NOT NULL, and
  every other type is claimed nullable). Verified there is **no Lua
  consumer** today — poste-db's editing/DDL paths get nullability from
  the introspection queries (`sql_introspect/*`, real IS_NULLABLE), so
  the field is inert. Options are removal (a wire-shape change —
  MAJOR per docs/schema.md, must ship in lockstep with siblings) or
  filling it from introspection (new query per statement — expensive).
  Neither is worth it while unconsumed; revisit if a sibling starts
  reading it.
- **Lua-side mirror drift, Lua repo's side of the pair**:
  poste-db's `exec_run.lua QUERY_PREFIXES` fallback classifier has
  grown CALL/EXEC/DESC entries that the Rust `QueryKinds` lists don't
  have. Harmless today (the Lua list only breaks ties when
  reconstructing legacy responses; the Rust event's `affected_rows`
  null-ness decides first) but it is exactly the "neither may drift
  alone" pair docs/schema.md names — next dialect work should
  reconcile or annotate.
- Carried unchanged from 09-13: layout byte/display-width mixing,
  `promise.finally_` double-invoke (still zero callers), non-nesting
  block comments in `split_statements`, `install.verify_checksum`
  skip-without-hasher.

## Verified this pass

- `timeout_secs == 0` means no timeout (`sql_exec_common::timed`) —
  matches poste-db's session transport passing `--timeout 0`.
- `normalize_dialect` (Rust) and `DIALECT_ALIASES` (Lua constants) are
  still in lockstep; alias→base-dialect URL building has parity tests
  on both sides.
- Percent-encoding parity: Rust `USERINFO_ENCODE_SET` and Lua
  `percent_encode` both encode exactly the complement of
  `A-Za-z0-9-._~` for user/password/database.
- Rust `to_url()` reads `connections.json`; the Lua resolver reads
  `connections.toml` and always passes `--connection <url>`, so the
  two files serve different flows by design (documented in AGENTS.md).
