# Code Review — 2026-09-15

Full re-read of the three crates after the family dissolution, plus a
line-by-line comparison of the Rust resolver against its Lua mirror
(poste-db.nvim `connections.lua` / `constants.lua`). Baseline: 453 tests
green, clippy `-D warnings` clean, `cargo fmt --check` clean.

## Bugs fixed (this change set)

1. **`--database` dropped the URL query string** (`poste-core/request.rs`)
   — `replace_database_in_url` rebuilt the URL from the last `/` and
   discarded everything after the db segment, so switching the database on
   `postgres://host/db?sslmode=require` silently lost the pinned
   `sslmode`. Query/fragment now survive the swap; sqlite (no `://`)
   still passes through untouched.

2. **Rust resolver had drifted from its Lua mirror** (`poste-exec/sql_connection.rs`)
   — three drifts against the documented "neither may drift alone" rule:
   - dialect aliases: only `mariadb` normalized; a connections.json entry
     with `postgresql` (or cockroachdb/yugabyte/…) produced an EMPTY url
     from `to_url()`. Full `DIALECT_ALIASES` table added.
   - sqlite paths with an existing query string got a second `?`
     (`f.db?cache=shared?mode=rwc`). Now `&mode=rwc`, pinned `mode=` kept.
   - the database segment was emitted raw; a db name containing `/`,
     spaces or unicode broke the URL. Percent-encoded now, matching Lua.

3. **A bad statement killed the session process** (`poste-cli/session.rs`)
   — the sqlite/postgres/mysql NDJSON loops let per-statement errors
   (any SQL error, and the per-statement timeout bail) `?`-propagate out
   of the loop: one typo'd statement terminated `poste session` and
   dropped the connection. mssql/clickhouse already reported statement
   failures as `status:"error"` events; all five paths now share that
   behavior via a common `error_result()` helper. Process-level
   regression test drives the real binary (`cli_sqlite_session.rs`).

4. **`normalize_sqlite_connection` did not append the create flag**
   (`poste-exec/sql_connection.rs`) — only `to_url()` added `?mode=rwc`,
   so exec-file/session given a plain `sqlite:/new/file.db` failed with
   sqlx's "unable to open database file (code 14)" unless Lua had already
   fixed the URL. Flag logic lives in a shared
   `ensure_sqlite_create_flag()` now.

5. **`{{var}}` resolution ignored the documented precedence**
   (`poste-cli/util.rs`) — schema.md specifies OS env > `.env` (walk-up)
   > env.json, and the Lua mirror implements exactly that; Rust read only
   the nested env.json section. `.env` parsing, flat-env.json tolerance
   and the OS-env overlay added (`vars_os` + `to_string_lossy` so a
   non-UTF-8 env var cannot panic the CLI).

6. **`detect_use_statement` could panic on exotic input**
   (`poste-core/sql_parser.rs`) — it validated `"USE "` against
   `to_uppercase()` but sliced the ORIGINAL at byte 4; case folding can
   change byte lengths (ſ/ß → SS), so the uppercased prefix proves
   nothing about a char boundary in the original. `get(4..)` now.

7. **Golden NDJSON fixtures for exec-file** (`tests/exec_file_golden.rs`)
   — three process-level cases (greedy mixed, transaction rollback,
   `--max-rows` truncation) run the real binary against a temp sqlite db
   and compare the full normalized event stream against committed
   goldens (`UPDATE_GOLDENS=1` regenerates). Created first, so the
   consolidation below could be verified byte-for-byte.

8. **The five-dialect duplication is consolidated** (see Revision
   record) — `poste-exec::sql_exec_common` (classification, timeouts,
   truncation, event builders, `run_sqlx_statement`) and
   `poste-exec::sql_values` (the value converters, single copy).
   exec_file.rs 1907 → 1261 lines, session.rs 922 → ~370 lines, wire
   shapes byte-identical on both transports.

## Recorded, not changed (with rationale)

- **`strip_sql_directives` (exec_file) duplicates
  `strip_directives` (sql_parser)** — same regex, exec_file's version
  additionally drops `###` lines. Candidate for the same consolidation.
- **`ConnectionConfig.ssl_mode` / `extra_params` are dead fields** —
  deserialized, never consumed (Lua passes resolved URLs; sslmode rides
  in the URL query). Kept for connections.json back-compat; a candidate
  for removal in the next MAJOR.
- **`poste connection list` reads connections.json while siblings
  resolve connections.toml** — the subcommand is documented as a
  "debug/parity helper"; making it TOML-aware means adding a TOML
  dependency to poste-exec. Carried until someone actually needs it.
- **`extract_database_from_url` shows a sqlite file stem that includes
  the query suffix** (`f.db?mode=rwc` → stem `f`) — display-only, in the
  summary event, pre-existing.
- **`blank_string_literals` intentionally ignores backslash escapes**
  (`\'`) — documented heuristic degradation, MySQL-only worst case.
