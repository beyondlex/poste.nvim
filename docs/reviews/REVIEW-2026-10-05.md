## Probed, held (recorded on purpose)

- **Transaction rollback verified against a live sqlite**: a batch of
  `CREATE TABLE` + `INSERT` + failing `INSERT` + `SELECT` under
  `--mode transaction` emits the error event, `rolled_back: true` in
  the summary, and leaves `sqlite_master` empty — the Lua side's
  "rolled back, no changes applied" branch rests on real behavior, not
  just the unit tests. The `record_commit` shape (a server-side COMMIT
  failure reported as a statement-shaped error event) is unchanged from
  round 20's review.
- **CRLF, BOM, non-UTF-8**: a CRLF file's `-- @connection` directive
  resolves and its statements run (the directive regex's `(.+)` keeps
  the value, `.trim()` drops the `\r`); a leading BOM is stripped by
  the parser (and `parse_request` trims it again for the session
  path); a non-UTF-8 file errors cleanly ("stream did not contain
  valid UTF-8").
- **The resultset column metadata's `nullable` field is
  `type_info().name() != "BOOL"`** (`exec_file.rs` and `session.rs`,
  byte-identical since the first exec-file commit, no rationale
  comment). As metadata it is nonsense on its face — a BOOL column is
  not specially NOT NULL — but it is also write-only: no Lua consumer
  reads `nullable` off resultset columns (the introspect path carries
  the real nullability from information_schema), and `docs/schema.md`
  documents only `columns[].name`. Recorded so a future consumer knows
  the field is garbage before wiring to it; fixing or removing it is a
  wire change with no reader, which is not worth making today.
- **Mirror check held**: the Lua `percent_encode`
  (`[^%w%.%-%_%~]`, byte-wise) and Rust `USERINFO_ENCODE_SET`
  (CONTROLS + every printable ASCII outside the unreserved set,
  non-ASCII bytes always encoded) encode the same set; both sides
  percent-encode user, password AND database; `url_host` brackets an
  IPv6 literal on both. The `-- @connection` directive anchors
  (`^\s*--\s*@connection\s+`) match the Lua `match_directive`
  pattern, both case-sensitive — consistent, so an uppercase
  `-- @CONNECTION` is a plain comment everywhere or nowhere.
- `is_use_statement` case handling (`use mydb;` skipped),
  `is_query_with`'s comment/literal blanking, and the session loops'
  per-statement error resilience were re-confirmed by their existing
  specs; the hostile-CLI probes of round 21 added nothing new.
