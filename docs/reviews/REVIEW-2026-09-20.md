# Code Review — 2026-09-20

Follow-up to `REVIEW-2026-09-19.md`. Scope: a fresh pass over statement
classification (the `is_query_with` / `is_query_stmt` family and the three
inline copies in the single-statement executors), the USE-detection
predicates, exec-file's URL display extraction, and — the headline — the
connection-store mirror contract, verified against
`poste-db.nvim/lua/poste-db/connections.lua` and `docs/schema.md`.
Baseline: `cargo test --workspace` green (466 → 479 with this pass's
additions), clippy 0 warnings, fmt clean.

## Bugs fixed

1. **Statement classification was blind to comments** — every classifier
   matched keywords against `blank_string_literals(stmt).to_uppercase()`,
   and that view keeps comments: a hinted `/*+ SeqScan(t) */ SELECT` did
   not start with "SELECT", fell through to the execute path and lost its
   rows (reported as `affected_rows`); the word "returning" inside a
   comment (`UPDATE t SET a = 1 /* returning to baseline */ …`) flipped
   DML onto the fetch path and dropped the affected count; mssql's
   `is_ddl_stmt` likewise missed commented temp-table DDL, which would
   have scoped it to the RPC prepare/execute scope. New
   `poste_core::sql_parser::blank_literals_and_comments` composes the
   literal blanking with comment removal (line comments keep their
   newline, each block comment collapses to one space — a comment is
   whitespace, so `SELECT/*x*/1` reads back as `SELECT 1`). Applied in
   `is_query_with`, mssql `is_query_stmt` and `is_ddl_stmt`. The three
   inline keyword lists in the postgres/mysql/sqlite single executors
   matched the shared `QueryKinds` constants byte-for-byte; they now call
   `is_query_with` so the lists can never drift.

2. **`ConnectionStore` never read `connections.toml`** — the mirror
   contract (`docs/schema.md`) names connections.toml as THE format and
   the Rust resolver as its parity implementation, but the store only ever
   looked for `connections.json`: `poste connection list/test` and the
   exec-file name fallback saw nothing for a TOML-only user — which is
   every sibling's shipped shape, so `:PosteDbConnection` → Test was
   broken for them. The store now walks up for `connections.toml` first
   (new `toml` workspace dependency) and keeps `connections.json` as a
   legacy fallback. TOML parsing is tolerant like the Lua resolver:
   top-level scalars and satellite/tunnel sub-tables are skipped, `port`
   accepts integer or string, and a missing `dialect` defaults to
   `postgres`. `schema.md`'s parity note is no longer aspirational.

3. **exec-file's summary event reported the query string as the database**
   (`crates/poste-cli/src/exec_file.rs`) —
   `extract_database_from_url("postgres://…/db?sslmode=require")` returned
   `db?sslmode=require`; `replace_database_in_url` already treats the
   `?suffix` as config when `--database` swaps the path segment, and the
   display extractor now makes the same split (fragments too).

4. **USE detection only accepted a trailing space** — `USE\tmydb` slipped
   past `is_skippable`, `detect_use_statement` and exec-file's pre-exec
   filter alike. `detect_use_statement` now compares the first
   whitespace-delimited token (still rejecting `USELESS`, still Unicode
   safe: `uſe db` uppercases its token, never a byte offset), and the new
   `is_use_statement` is the one predicate the exec-file filter and
   `is_skippable` share — `total` and event numbering can no longer
   disagree about what a USE is.

## Recorded, not changed (with rationale)

- **`ssl_mode` is parsed but never applied** — `ConnectionConfig` carries
  it, the new TOML loader reads it, but `to_url()` does not append
  `?sslmode=`, and the Lua mirror ignores the field entirely. The two
  mirrors agree (no drift), nothing documents the field, so nothing
  silently misbehaves — but it is a candidate feature: honoring it for
  postgres (`?sslmode=<value>`, a libpq-standard query param sqlx parses)
  would be a real behavior change to the resolution contract and deserves
  a deliberate cross-repo pass.
- **`connection.rs`'s Test action still re-implements the five-field
  `substitute_vars` pass instead of calling `store.resolve`** (carried
  from 09-19, untouched today).
- **`redis_executor.status_text` renders the full BulkString payload** —
  a multi-megabyte value makes a multi-megabyte status line while the
  structured `value` honors `max_bytes`; Lua consumes `value`, so this is
  latent memory churn, not a wire-shape bug.
