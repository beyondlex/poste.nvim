# Code Review — 2026-09-07

Scope: all of `lua/poste/` (the shared Lua layer) plus a targeted pass over
`crates/` focused on statement boundary detection. Baseline: `cargo test` 87
green; the Lua layer had **no test infrastructure at all** before this pass.

## Bugs fixed

1. **`find_all_statement_ranges` split `FOR UPDATE` into phantom statements**
   (`crates/poste-core/src/sql_context/statements.rs`) — the containment check
   for UPDATE-as-clause (`SELECT … FOR UPDATE`, `INSERT … ON CONFLICT DO
   UPDATE`) was gated on `stmt_start > 0`, so the *first* statement in a
   buffer got split: `SELECT 1 FOR UPDATE; SELECT 2;` yielded four ranges
   instead of two (empirically confirmed before the fix). Boundary handling
   also pushed whitespace-only gaps between `;` and the next keyword as
   phantom statement ranges.
   - containment now applies regardless of position (an empty slice at
     position 0 still means a standalone `UPDATE` is a real statement)
   - ranges go through `push_stmt_range`, which skips leading
     whitespace/comments and drops empty ranges
   - 8 regression tests; feeds `poste context --action stmt-ranges`
     (multi-statement execution boundaries in poste-db.nvim)

2. **`layout.dynamic_line` byte/char offset confusion** (`lua/poste/layout.lua`)
   — left/mid truncation derived keep-offsets from byte length (`#s`) but
   `strcharpart` takes CHAR indices, so multi-byte text truncated at wrong or
   mid-character positions.

3. **`install.ensure()` ignored `vim.g.poste_binary`** (`lua/poste/install.lua`)
   — a user pointing the override at a dev/worktree build still triggered a
   release download at startup when the default data path was empty. The
   resolution order now matches `state.find_poste_binary()`.

4. **`verify_checksum` rejected good downloads where no hasher exists**
   (`lua/poste/install.lua`) — on systems without `sha256sum`/`shasum`
   (Windows), the digest comparison ran on garbage and failed the download.
   Now checks `executable()` first, adds a `certutil` fallback, and skips
   verification (like a missing checksum file) when no SHA256 tool exists —
   with an explicit warning.

5. **`cargo fmt` drift** — several files had drifted and the CI
   `cargo fmt --all --check` gate was failing on main; reformatted (no
   behavior changes outside sql_context).

## New: Lua test suite

`tests/run.sh` + `tests/poste/` (plenary), mirroring the sibling repos:
layout (wrap/pad/truncate incl. the multi-byte regression), util, promise
chain semantics, and state keymap/binary-resolution helpers — 32 tests, all
green. The shared Lua layer had zero coverage before.

## Recorded, not changed

- **`async/promise.lua` has zero callers** across the ecosystem (grepped
  poste.nvim, poste-db.nvim). `M.new(resolve_fn, reject_fn)`'s two-argument
  form also executes `reject_fn` *immediately* at construction — surprising,
  though only `M.reject` uses that form. Left in place as future API; if it
  stays unused, deleting it is the better call.
- **`indicators.clear_other_requests(buf, _line_0)`** ignores its `line_0`
  argument and clears every extmark in the namespace. Name promises more than
  it does; kept because callers exist.
- clippy warnings are informational in CI (per its config); a handful remain
  (needless mut, unused `parse_uri`, `map_or` simplifications).
