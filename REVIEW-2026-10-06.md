## Bugs fixed

1. **SQLite wide integers shipped as JSON numbers** (`sql_values.rs`).
   `sqlite_value_to_json` returned every i64 cell bare — no max-safe
   guard — while the pg and mysql BIGINT arms both send magnitudes past
   2^53 as exact-digit strings, and the poste-db bigint spec pins that
   contract ("bigints above 2^53 arrive as JSON strings"). Measured, not
   inferred: `exec-file` of `SELECT 9223372036854775807` emitted the bare
   number, which rounds silently in the Lua decoder — the grid displays
   9223372036854775808 and a commit written from that cell stores the
   rounded value. The sqlite arm now applies the same
   ±9_007_199_254_740_992 rule. Pinned by an in-memory-sqlite test
   asserting i64::MAX / i64::MIN arrive as strings and 42 stays a number.
   docs/schema.md now states the rule as dialect-uniform.

2. **A blank SQL request got no response** (`session.rs`). All five
   dialect loops handled `Request::Blank` with a bare `continue` — the
   request's seq was answered with SILENCE, so any client pairing
   responses to the seqs it sent desynced. It was not hypothetical:
   poste-db's executor.lua carries a guard comment describing exactly
   this ("the session transport answers nothing for a blank request…
   the request stays in session.pending forever") and refuses blank SQL
   before the wire to keep its pending map from leaking an entry. The
   variant now carries the seq and every loop answers
   `{"status":"error","error":"Empty statement"}` — one request, one
   response — while the loop keeps serving. Pinned by the sqlite session
   integration test (blank request → error event with the right seq →
   next request still served), and docs/schema.md spells the total-loop
   contract out.

## Probed, held (recorded on purpose)

- `exec-file` with a comments-only file errors cleanly ("No SQL
  statements found"); CRLF + BOM files parse to the right statement
  count; a 5000-statement file streams all 5000 results; an unbalanced
  quote comes back as an error event, not a crash.
- `context stmt-ranges` keeps an unterminated block comment swallowing
  the rest of the input (the server reads it the same way), respects
  `;` inside string literals, `$fn$ … $fn$` dollar quotes and `\'`
  escapes, and answers `[]` for empty input.
- The session loop answers a garbage line with a seq-0 JSON-parse error
  event and keeps serving; exit stays 0.
- The non-test unwrap surface is `env.rs`'s static regex plus test code;
  `redis-exec`/`mq-exec` take their connection from stdin JSON (the
  `--connection` flag does not exist there, matching docs/schema.md).
- `redis_executor.rs` re-read against the Lua contract tests held: the
  per-byte `\xHH` Cc escaping, the `item_truncated`/`value_truncated`
  flags, the `cap_bytes` boundary handling and the RESP3 arms all have
  consumer-side pins in poste-redis.

## Architecture smells (recorded, not acted on)

- **The five session dialect loops are near-copies** (~50 lines each,
  differing in connect + executor closure). Live evidence of the cost:
  today's Blank fix had to be hand-applied five times and could have
  been applied to four. A loop parameterized by (connect fn, runner
  closure) would collapse them; moderate-risk refactor for a quiet
  round, not churn in a bugfix round.
- **The vendored-copy pins go stale by design**: poste-redis's
  `toml.lua` header pins a poste-db commit (`2216036`), but HEAD keeps
  moving on both sides. The tail-diff check used today
  (`diff <(tail -n +20 redis-copy) db-copy`) is the cheap mechanical
  guard; worth a line in the vendor headers themselves so the next
  syncer knows the command.
- **`REVIEW-*.md` accumulation at the repo root** (25 files and
  growing) — historical round logs living next to README/LICENSE. A
  `docs/reviews/` move is cosmetic; recorded because the root is the
  repo's first impression, not because it blocks anything.
- **The cross-repo wire contract has no single mechanical check**:
  each repo pins its side, and `display_command`'s round-trip test
  inside `redis_executor.rs` is the one place that simulates the Lua
  re-parse. The pattern generalizes (a shared fixture both sides
  consume); recorded as the highest-leverage future test investment.
