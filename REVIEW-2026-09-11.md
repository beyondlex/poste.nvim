## Bugs fixed

1. **Statement classification tripped on "returning" inside string
   literals** (9 sites: `exec_file.rs` ×3, `session.rs` ×3,
   `sql_executor/{postgres,mysql,sqlite}.rs`) —
   `upper.contains("RETURNING")` matched the word inside a literal:
   `UPDATE t SET note = 'returning'` or
   `INSERT INTO log (msg) VALUES ('returning item')` ran on the fetch
   path and reported `row_count 0` with no `affected_rows` instead of
   the DML count (the 09-09 poste-db round fixed the Lua-side
   `is_query_sql`; the Rust execution layer kept the substring find).
   Adds `poste_core::sql_parser::blank_string_literals` — a same-length
   char view with single/double-quoted and Postgres dollar-quoted
   contents blanked — and classifies on it everywhere. Tests: helper
   unit suite + an exec-file integration regression (INSERT/UPDATE with
   'returning' literals report `affected_rows 1`).

2. **TEXT cells that merely look like scalar JSON were coerced**
   (`sql_executor/sqlite.rs`, `exec_file.rs` value converters ×3
   dialects) — every TEXT/BLOB value ran through an unguarded
   `serde_json::from_str`, so the text `"123"` became the JSON number
   123 and the text `"null"` became SQL-NULL in the results panel. pg/
   mysql only auto-parse *declared* JSON columns; SQLite has no column
   type to gate on, so the gate moves into
   `poste_core::sql_parser::parse_json_cell`: only values starting with
   `{` or `[` parse (json_object()/json_array() output stays
   structured, scalars stay strings). Tests: helper unit suite + an
   sqlite end-to-end regression ('123'/'null'/'true' round-trip as
   strings, array/object still parse).

3. **`download()` reported success with no binary present**
   (`lua/poste/install.lua`) — the tar/Expand-Archive result was never
   checked; a corrupt archive or full disk fell through, stamped the
   `.version` file and notified "Installed". Extraction now verifies the
   binary exists before writing the version stamp.

4. **`event once()` spec raced its own assertion**
   (`tests/poste/event_spec.lua`) — emit reports failures via
   `vim.schedule`, but the test counted notifications synchronously;
   observed failing once in this round's first run (green in the 09-09
   round = luck). The count now waits on `vim.wait` for the queue to
   drain; three consecutive clean full-suite runs after the fix.

## Recorded, not changed (with rationale)

- **`async/promise.lua` and `state/event.lua` still have zero callers**
  across the ecosystem (re-grepped poste-db/poste-ai/poste-http this
  round) — carried from 09-08/09; deleting stays the better call unless
  a satellite adopts them.
- **`split_raw_blocks` treats any line starting with `###` as a block
  separator**, including `####` headers — matches REST-client
  conventions; renaming `#### comment` separators is on the user.
- **HTTP header heuristic**: a body line like `{"k": "v"}` directly
  after the request line (no blank separator) parses as a header —
  inherent to the REST-client file format; blank-line convention
  avoids it.
- **`blank_string_literals` does not interpret backslash escapes**
  (`\'` in MySQL strings) — a heuristic view, not a parser; worst case
  degrades to the pre-fix behavior for that one statement.
- **`is_query_stmt` (mssql/clickhouse) left untouched** — prefix-only
  checks, no `contains()`, nothing for literals to trip.
- clippy warnings informational — carried from 09-07/08/09.
