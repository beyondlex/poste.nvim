## Fixes (each with tests)

- **An unterminated dollar body now runs to end of input in the
  tokenizer** (`sql_context/tokenizer.rs`). `scan_dollar_quote` returned
  `None` — ordinary character — whenever the remainder after a *valid*
  tag opener contained no further `$`, so a `;` the user typed inside a
  body they were still typing re-opened live-SQL tokenization:
  `context stmt` / `stmt-ranges` split the editor's statement map there
  while `split_statements` (and the server, which answers
  "unterminated dollar-quoted string" for the whole rest) treat the
  buffer as ONE statement. run-statement-under-cursor and run-file
  disagreed about what executes; verified live on the binary before and
  after (`[[0,0],[1,1]]` → `[[0,1]]`, now matching exec-file's single
  statement). `None` stays reserved for the tag-grammar failures
  (`$1`, `$a` with no closing `$`), which is what the docstring always
  claimed.
- **`display_command` escapes C1 controls as UTF-8 bytes**
  (`poste-exec/src/redis_executor.rs`). The escape wrote one `\xHH` per
  *codepoint*, so the Cc range above DEL (U+0080–U+009F, two UTF-8
  bytes) lost its 0xC2 lead byte: a key `a<U+0085>b` echoed as
  `"a\x85b"`, and the Lua panel's re-parse (`string.char` per `\xHH` —
  raw bytes) rebuilt a lone 0x85 — a different, invalid-UTF-8 key than
  the one Redis replied with. That is the silent wrong-target refresh
  the quoting exists to prevent (the function's own docstring says so).
  One `\xHH` per UTF-8 byte now. The Lua mirror (`render_command`)
  passes these bytes through verbatim and always has; both readings
  round-trip.

## Change

- **`context stmt` / `stmt-ranges` accept `--dialect`**
  (`find_statement_span_with` / `find_all_statement_ranges_with`).
  `find_statement_span` tokenized with the standard reading only, while
  exec-file splits the same buffer with `escapes_for(dialect)` — on
  MySQL an `'it\'s'` literal closed early under the standard reading,
  re-opened a phantom string, and put the cursor's statement boundary
  somewhere run-file does not split. Default stays `generic` (today's
  behavior); `tokenize()` became test-only so every lib caller names
  the reading explicitly. The Lua statement map (poste-db f7e41ef)
  passes the buffer's resolved dialect.

## Read, not changed (recorded on purpose)

- **A rescue retry can re-execute a non-idempotent command.** When the
  first attempt reaches the server but the reply is lost, the
  connection-class error triggers one retry — `INCR` counts twice.
  Inherent to retry-after-loss; bounded to one attempt by design.
- **A SQL session holds one connection for its lifetime and never
  reconnects.** A dropped TCP (laptop sleep) keeps erroring until the
  Lua side restarts the session. Deliberate: a watchdog like the redis
  pool's would kill healthy long queries (the round-47 note in
  poste-db's `docs/REVIEW-2026-09-30-error-ux.md` reaches the same
  verdict for the pool).
- **`MssqlDdl::rename_column` breaks on a name containing `'`.** The
  sp_rename first argument is a single-quoted string built from
  bracket-quoted identifiers; `q()` does not escape `'`. No production
  caller — the trait doc records that only `create_table` is wired.
- **The tokenizer sees no non-ASCII identifiers.** Identifier scanning
  starts at ASCII letters/underscore; `SELECT 列名` produces no tokens,
  so completion context around such a name degrades (no crash, empty
  prefix). A family-wide limitation — the Lua side lexes the same set.
  Revisit only if a dialect user actually needs it.
