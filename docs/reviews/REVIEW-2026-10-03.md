Round 20, following `REVIEW-2026-10-02.md`. Scope: hostile probes of

## Fixes (each with tests)

- **A present non-string publish field now errors instead of
  publishing** (`poste-exec/src/mq_executor.rs`). `op_publish` read
  `payload` / `routing_key` / `queue` / `exchange` with
  `as_str().unwrap_or_default()`: a payload of `123` published the
  EMPTY payload, a routing key of `5` published to the empty route —
  with `routed: true` in both cases. That is a silent wrong-target
  write, the exact class the mandatory+confirm machinery exists to
  surface. The resolution moved into a pure `publish_parts` that fails
  closed on present-but-not-a-string (`null` counts as absent; the
  queue-targeted default-exchange form and fanout's missing routing key
  stay legal; `queue` still wins over `exchange`). The error text names
  the field and the JSON type it got, and never echoes the value.
- **`execute_operations_with`'s close is teardown, not a result**
  (same file). `connection.close(0, "").await?` ran AFTER every outcome
  had been delivered to the caller; a teardown hiccup there turned a
  fully-successful batch into exit 1 with the summary event swallowed —
  the Lua side sees a dead process after complete results. The redis
  executor simply drops its connection; the close error is now
  discarded for the same reason.

## Verified, not changed (mirror-pair sweep)

- **`.env` value substitution parity** — Lua's `parse_dotenv`
  pre-substitutes `{{VAR}}` inside `.env` values; the Rust copy stores
  them raw. Not drift: the Rust substitution runs at the use site and
  iterates to a fixed point (cap 10, matching Lua's depth cap), so
  `BASE=example.com` + `DB_URL=postgres://u:p@{{BASE}}/db` resolves to
  the same URL on both sides. `env.rs`'s tests pin the fixed point and
  the cycle cap; `sql_connection.rs`'s
  `store_loads_toml_and_resolves_the_same_urls_as_lua` pins the URL
  surface.
- **`util.rs`'s env table** — `scalar_vars` (numbers/bools are values,
  objects/null skipped), the `envs` wrapper, the flat form, and the
  OS-env-highest precedence all carry tests, and the Lua
  `scalar_env_vars` doc comment names the Rust mirror it copies.
- `sql_values.rs` — read-only pass; the non-finite float spellings,
  the BIGINT safe-integer band, and the DECIMAL→f64 round-trip guard
  are correct as documented and tested.
- `mq_session.rs` — read-only pass; `consumer_start_target` already
  fails closed on a missing/empty/non-string queue and a non-boolean
  ack (both silence-based traps documented in its tests).
