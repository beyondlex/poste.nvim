## Bug fixed

1. **The redis command echo was a bare `tokens.join(" ")`** (`9580f44`).
   The echo travels back to the Lua panel as `result.command`, where it
   is not just displayed — it is RE-PARSED (tab refresh, history replay,
   `gd` all run it through the Lua tokenizer). For a binary-safe key the
   decoded token carries a real newline, so `GET "a\nb"` echoed as
   `GET a⏎b`: the re-tokenizer split the key into `a` and `b` (a silent
   wrong-target refresh), and the raw newline reached `nvim_buf_set_lines`,
   which rejects lines with embedded newlines and crashed the panel
   render.

   `display_command` (new, `pub`) emits the redis-cli quoted form —
   tokens that are empty or carry whitespace, a quote, a backslash or any
   control char are double-quoted with `\"`, `\\`, `\n`, `\t`, `\r` and
   `\xHH` for other controls, exactly the escape set the Lua
   `unquote`/`render_command` pair speaks. `execute_command_on` and
   `redis_session.error_outcome` both use it, so one-shot and session
   mode echo identically. Four tests pin the shapes, including a
   round-trip through a tokenizer mirroring the Lua side's rules.
