# Code Review — 2026-09-09

Follow-up to `REVIEW-2026-09-07/08.md`. Scope: re-read of `lua/poste/`
(state, util, cli, core, constants, error, state/event) and targeted Rust
passes over `exec_file.rs` (directive stripping, USE filtering, transaction
begin/rollback/commit flow) and `poste-exec` value serialization. Baseline:
`cargo test` workspace green, Lua suite 42 green, luacheck 0 warnings.

## Bugs fixed

1. **`event.once()` left a failing handler subscribed**
   (`lua/poste/state/event.lua`) — the one-shot wrapper called the handler
   bare; when it errored, the unsubscribe loop never ran, so every later
   `emit` re-ran the handler and reported the failure again. A `once`
   handler that throws is now unsubscribed before the error is rethrown
   (emit's pcall still reports it once). The bus had no tests at all;
   `tests/poste/event_spec.lua` covers deliver/unsub/once/failing-handler
   isolation/clear.

## Recorded, not changed (with rationale)

- **`async/promise.lua` and `state/event.lua` have zero callers** across
  the ecosystem (re-grepped poste-db/poste-ai). The 09-07 note stands and
  now applies to both: unless a satellite adopts them, deleting is the
  better call. The `once` fix above was still worth landing — if the bus
  stays, its semantics should be right; if it goes, it goes tested.
- **`indicators.clear_other_requests(buf, line_0)` ignores `line_0`** —
  carried from 09-07.
- **clippy warnings informational** — carried (needless borrows in
  introspect, `unused_mut`, single-pattern `match`, unused `parse_uri`).
- **`exec_file.rs` USE filter matches `USE ` as the whole uppercase head**
  (`trim().to_uppercase().starts_with("USE ")`) — a statement like
  `USER ...` cannot occur as valid SQL head, so the space terminator is
  sufficient; noted only for symmetry with the Lua-side keyword matching.
