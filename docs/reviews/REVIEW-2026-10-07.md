## Bugs fixed

1. **A mid-UTF-8 cursor offset panicked the whole `context detect`
   subcommand** (`sql_context/context.rs`). The CLI passes the cursor
   offset to `detect_context` as a bare `usize` from the wire, and the
   whitespace look-back slices `&sql[..offset]` — an offset landing inside
   a multibyte character (byte 8 of `SELECT 你好`, inside 你) panicked
   instead of answering, and a panic in the binary is an exit-101 with a
   stack dump where the editor expected one JSON line. `detect` now floors
   a mid-char offset to its starting char boundary; past-end offsets keep
   their pinned Keyword answer (the `find_token_at_offset` → None → 0
   route), which the existing
   `test_detect_offset_past_end_falls_to_last_semantic_token` already
   pins. Pinned by offset sweeps over CJK text, an NBSP and an ideographic
   space (every byte offset must answer without panicking) and a
   hostile-text table (`'''`, `$$$`, NUL and DEL bytes, lone emoji).

## Probed, held (recorded on purpose)

- The hostile-text table above (empty input, quote/dollar soup, comments
  under one byte, `SELECT * FROM t WHERE x = ` with the cursor past the
  end) all answer without panicking, before and after the fix.
- `find_statement_span_with` / `find_all_statement_ranges_with` on empty
  input, an out-of-bounds cursor line, unterminated strings/comments and
  `;;;\u{feff};` shaped lines: `None` / `[]` / the honest span, no panic.
- The non-test `unwrap` surface is still `env.rs`'s static regex plus test
  code only; `exec_file.rs`, `sql_connection.rs` and `sql_introspect/mod.rs`
  keep every `unwrap*` inside `mod tests`.
