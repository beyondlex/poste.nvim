## Bugs fixed

1. **The Rust resolver dropped a raw `url =` entry and probed localhost**
   (`sql_connection.rs`, commit `2503dce`). docs/schema.md rule 4 puts a
   raw `url = "…"` entry in the family contract and the Lua resolvers
   honor it, but `connections_from_toml` never read the field: the store
   resolved `[prod] url = "postgres://db/prod"` to
   `postgres://localhost:5432/` from the defaults — `poste connection
   test` and exec-file's named `@connection` directive probed the WRONG
   server (and could pass) while the editor reached the real host.
   `ConnectionConfig` carries the url now: `to_url` passes it through
   verbatim (empty string falls back to the field form, the same reading
   as Lua), `with_vars_resolved` substitutes `{{vars}}` in it, and the
   TOML loader keeps it. Verified end to end: a `url = "sqlite:probe.db"`
   entry creates the file through `@connection prod`.

2. **A named `###` section marker rode into the next statement**
   (`sql_parser.rs` + `exec_file.rs`, commit `093f5c3`). The local filter
   matched only a bare `line.trim() == "###"`, while the Lua editor reads
   any `^%s*###` line as a marker (`SECTION_MARKER_PATTERN`). A named
   header — the shape the editor writes (`### users by signup`) — stayed
   in the body, glued itself to the next statement, and the server
   rejected the statement with `unrecognized token: #`: every
   named-section file failed on the CLI that the editor executed fine.
   `strip_directives_and_sections` drops directives and markers through
   one literal-aware, top-level-only pass (a `###` line inside a
   multi-line string is data; the BOM strips before the match). Verified
   end to end against sqlite::memory:. schema.md's exec-file section pins
   the rule now (`bc75ff4`).

## Probed, held (recorded on purpose)

- `split_statements_with` still treats named `###` markers as statement
  content — only the exec-file entry strips them now. The `context`
  subcommand's statement ranges on a named-section file are shifted by
  the marker lines; the editor computes navigation itself (Lua side), so
  nothing consumes those ranges against the raw file today. Revisit if a
  consumer appears.
- `parse_port` mirrors Lua's `tonumber` for decimals but NOT for hex:
  Rust's f64 parse refuses `"0x10"`, LuaJIT's tonumber accepted it — the
  Lua sides were aligned to Rust's decimal grammar the same day
  (poste-db `868bdef`, poste-redis `a1f4d6a`), so this side did not move.
- `ConnectionConfig::ssl_mode` / `extra_params` parse but nothing
  consumes them (`to_url` ignores both; no executor reads them). Dead
  fields from an earlier era — removing them is a serde wire change, so
  they are recorded here rather than deleted mid-round.
- The legacy `connections.json` fallback has no Lua mirror (the editor
  reads only connections.toml). Documented as legacy; asymmetry accepted.
- `display_token` quotes Unicode Cc (U+0080–U+009F included) while the
  Lua `render_command` mirrors quote C-locale `%c` only; the re-parse
  contract is one-directional (Lua re-parses the Rust echo), so the
  asymmetry is benign.
