## Bugs fixed

1. **A leading UTF-8 BOM blinded the `-- @connection` directive**
   (`exec_file.rs`, commit `b4cbf4a`). `strip_directives` drops a leading
   U+FEFF before its own directive match (and the statement splitter
   strips one too), but `extract_connection_directive` read the raw file:
   a file saved by a BOM-writing editor carried a valid directive line
   the regex could not see (`\s` does not match U+FEFF) and failed with
   "No connection specified". The Lua resolvers had the same hole in
   `constants.match_directive` (fixed in poste-db the same day); schema
   rule 6 now pins the BOM-tolerant reading on both sides. Pinned by a
   BOM spec including the mid-file-BOM non-match.

## Probed, held (recorded on purpose)

- Comment-only and USE-only files fail with the two distinct
  "no executable statements" errors; CRLF bodies split correctly; a
  deferred-FK COMMIT failure (`PRAGMA defer_foreign_keys=ON`) reaches the
  stream as a `COMMIT` error event with `rolled_back: true` — the
  record_commit contract holding end to end.
- `extract_database_from_url("sqlite:/dir/f.db?cache=shared")` reports
  `f` (file_stem splits at the last dot, query included in the
  extension); display-only, and the name a user recognizes.
- `--database` on a sqlite URL stays a documented no-op
  (`replace_database_in_url` non-URL passthrough).
- The `parse_dotenv` mirror pair reads a `.env` line differently at the
  margins: the Rust copy accepts any key up to `=` and `strip_prefix(
  "export ")` (exactly one space), the Lua copy wants `[%w_.]+` keys and
  `^export%s+`. A key outside dotenv convention (`MY-KEY=`,
  `export\tK=`) resolves in the CLI and stays literal in the editor.
  Recorded, not fixed: both readings cover every shape dotenv files
  actually carry, and tightening either side alone would reopen the
  drift the pair exists to prevent.
- The non-test `unwrap` surface is still test-only (re-scan of the exec,
  redis, mq, sql_executor and sql_context modules).
- `sql_ddl.rs`'s unwired members (REVIEW-2026-09-21) carry one new latent
  trap worth naming for whoever wires them: `MssqlDdl::rename_column`
  interpolates `quote_identifier` output (double-quoted identifiers)
  into a single-quoted T-SQL string for sp_rename — a name containing
  `'` would close that literal. Dead code today (`create_table` is the
  only production caller); the Lua-side `table_ops.gen_rename_column`
  already routes mssql through `quote_literal` and is the correct shape
  to copy if the Rust path ever ships.
