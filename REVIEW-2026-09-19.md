## Bugs fixed

1. **A lone quote in a variable value panicked the CLI**
   (`crates/poste-core/src/parser/mod.rs`) — `@v = "` satisfied both
   `starts_with('"')` and `ends_with('"')` on a one-byte string, so
   `strip_quotes` sliced `1..0` and the process died with a range panic
   instead of keeping the literal character. The `len() >= 2` guard the
   `.env` reader in poste-cli's `util.rs` already applies is now in
   place here too, with a regression test covering both quote styles.

2. **Introspection interpolated table names into SQL unescaped**
   - `crates/poste-exec/src/sql_introspect/mysql.rs`: `SHOW FULL
     COLUMNS FROM \`{}\`` / `SHOW INDEX FROM \`{}\`` took the raw name
     inside backticks — a backtick in the name broke the query
     (clickhouse and mssql already escape via their `inline()` helpers).
   - `crates/poste-exec/src/sql_introspect/sqlite.rs`:
     `pragma_foreign_key_list('{}')` took the raw name inside single
     quotes; pragma arguments cannot be bound as parameters, so a quote
     in the name broke the FK lookup silently (`unwrap_or_default`).
   Both sites double their respective quote character now, matching the
   escaping the mysql FK query already applied.
