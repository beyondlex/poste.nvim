# Code Review — 2026-09-17

Follow-up to `REVIEW-2026-09-16.md`. Scope: the redis wire surface the
sibling plugin rides — `poste-exec/src/redis_executor.rs` (value shaping,
truncation, reply-type inference) and `poste-cli/src/redis_session.rs`
(timeout/rescue loop) — plus a panic-pattern sweep of the SQL value
converters and DDL generators. Baseline: `cargo test` workspace green
(462 → 464), clippy `-D warnings` clean, `cargo fmt --check` clean.

## Bugs fixed

1. **Bulk-string truncation cut mid-character and panicked**
   (`redis_executor.rs`) — the `--max-bytes` cut was `&s[..max_bytes]`,
   which panics when the byte index lands inside a multibyte UTF-8
   sequence. A CJK/emoji value whose max_bytes-th byte continues a
   character killed the whole `redis-exec` / `redis-session` process
   mid-batch (every pending request in the Lua session then failed at
   once). The cut now floors to the previous char boundary. The existing
   ASCII truncation test could never catch this; a CJK case pins it.

2. **MGET/HMGET replies inferred as hash maps** (`redis_executor.rs`) —
   both reply with one value per requested key/field; a flat even-length
   string array hit the even-count heuristic and rendered as a HASH, so
   `MGET a b` displayed as `{a: <value of a>}` — the values became fake
   keys in the panel grid. Both commands now infer list like LRANGE.

## Recorded, not changed (with rationale)

- **The even-count hash heuristic remains a misread risk for any
  unlisted command** whose reply happens to be an even-length flat
  string array (e.g. `CONFIG GET`-shaped replies from new commands).
  Every fix narrows the heuristic by whitelisting; the alternative
  (requiring an explicit command table) is the same list, just louder.
- **redis-session COMMAND_TIMEOUT (30 s) vs the sibling's Lua watchdog
  STALL_LIMIT (10 s)** — the watchdog restarts a "stalled" session
  before the binary's own rescue path reports. Both recover; the
  mismatch is documented in poste-redis's 2026-09-17 record.
- **`sql_values.rs` JSON-parses every string cell** (`parse_json_cell`)
  — a TEXT column storing `{"a": 1}` surfaces as a parsed JSON object on
  the wire. Intentional (the dataset renders it tree-able); flagged only
  because it means the wire value type is content-dependent, not
  schema-dependent.
